# ShopPilot · 电商导购智能体

> ⚠️ **免责声明**：本项目为个人学习练习项目。代码、商品池/评论/销量等全部数据、
> 知识库文档与题库均为**自行生成（LLM 合成，结构模仿巴西 Olist 开源数据集）**，
> **仅供参考练习之用**，不代表任何真实企业业务，不可用于商业用途。

## 这是什么

面向消费者的电商导购 Agent。用户输入自然语言需求（"预算500推荐降噪耳机 / A和B怎么选 / 这商品翻车点在哪 / 保修多久"），Agent 结构化抽取约束 → 并行查询商品池、口碑与售后知识库 → 输出带依据编号的推荐清单卡、对比卡、避坑提示，并跨会话记住用户偏好。

**五大导购场景**：选购推荐 / 商品对比 / 口碑解读 / 售后问答 / 超范围拒答。

## 设计思路

一句话：**LLM 负责"理解和表达"，确定性代码负责"计算和校验"。** Agent 系统的价值不是让 LLM 更强，而是用工程护栏把它的不稳定性关进笼子。

### 三部件编排

系统运行时只有三个部件，刻意收敛不为分层而分层：

1. **规划（Planner）**：把用户自由文本抽成结构化需求（意图/实体/预算/在意维度），用 `json_object` 强制合法 JSON，再过 Pydantic 契约校验；然后拆成子任务 DAG（有向无环图）。拆错了会触发一次重写。
2. **执行（Executor）**：子任务按拓扑分层，同层无依赖的用线程池并发执行。data/review 类任务走有界 ReAct 循环（思考→调工具→观察→再思考），knowledge 类走 RAG 检索。循环有三重预算护栏（最多8步/token 6万/成本0.5元），任一超限即降级返回，不无限烧钱。
3. **成稿（Composer）**：聚合各子任务结论 → 生成结构化产出卡（推荐卡/对比卡/避坑清单）→ 强制引用编号 → 五项确定性自检（引用越界/超预算/商品溯源/误拒答/目标覆盖），不过关触发一次修复。

### 两个记忆

- **短期记忆**：最近6轮对话原文进滑窗，更早的由 LLM 压成≤150字滚动摘要。解决长对话变傻（窗口限制+注意力稀释+token成本）。
- **长期记忆**：跨会话 Markdown 文件追加式（每轮对话结束追加一条：问了什么、答了什么、涉及哪些商品、结论要点），下次对话按关键词命中检索最相关的几条注入 Planner。用户可直接打开看、可删。

### 推荐排序：七维加权打分在工具内

推荐不是"按评分排序"，而是工具内做七维加权打分：价格贴合 13% / 平台评分 16% / 评论均分 10% / 销量热度 8% / 好评匹配 22% / 差评风险 18% / 物流时效 13%（次日达是电商转化关键信号）。输出带总分、分项得分构成、好评/差评原文、decision_reason 草稿——LLM 只负责把草稿组织成自然语言，不负责计算。这样排序可回归（改权重 benchmark 跑一遍就知道好不好），不会出现"同一批商品两次打分 LLM 给出不同排序"的不一致。

### 售后 RAG：TF-IDF + BM25 + RRF 融合

售后问题走 RAG：向量路（TF-IDF char n-gram）懂语义但怕专名数字（"鼓包""发票"召回差）；BM25 路对型号/数字/专名极准但不懂同义。RRF 融合 `score = Σ 1/(60+rank)`，两路共识 chunk 排最前。按 Markdown 标题结构感知切分（不硬切断段落），强制引用溯源——售后答错=客诉，资料不足诚实拒答不硬编。

## 创新点

| 创新点 | 为什么重要 |
|---|---|
| **多轮槽位继承** | 用户说"买耳机→顺带买充电线"自动识别为配套场景，继承上一轮预算与在意维度，不重新推荐耳机 |
| **七维打分可回归** | 排序是数学题，放工具内确定性计算；改权重可回归，不让 LLM 每次给出不一致排序 |
| **五项确定性自检** | 引用越界/超预算/商品溯源/误拒答/目标覆盖——纯函数规则零 token，LLM 自评有自我讨好偏差不可靠 |
| **库外实体闸** | 池外型号（如 iPhone）直接拒答，不编造价格——防编造的第一道闸 |
| **推荐依据可溯源** | 每个推荐结论后带 [n] 引用编号，点开是工具返回的真实数据或知识库原文，不是 LLM 凭空生成 |

### 为什么不采用这些常见方案

- **MemGPT 式 LLM 自管记忆**：让 LLM 自己决定往核心记忆写什么，经常漏掉关键实体（比如用户说"给爸爸买"被忘掉）；本项目用显式槽位+滑窗，记忆写入过筛（只记用户明确表达过的），更稳。
- **Milvus/向量数据库**：长期记忆条目在几十条量级，jieba 分词+关键词命中已经够用；上向量库是过度工程，且用户不可读不可删。
- **多智能体（>3个角色）**：电商导购是窄域任务，三个部件足够；上更多角色是调试地狱，错误累积放大（每个 agent 都可能出错）。
- **自动画像推断**：推断错一次（把"给爸爸买"推断成"用户自己要"）信任就崩了；只记用户明确说过的预算/在意维度，不猜。
- **32K 长上下文替代 RAG**：政策文档更新一次就要重跑全量推理，且检索不可控（模型可能漏读关键段落）；RAG 按需检索+强制引用更可控。

## 示例提问（五大场景 + 连续追问）

### 单轮提问
- 🎁 **选购推荐**："预算500以内推荐一副降噪耳机"
- ⚖️ **商品对比**："蓝牙耳机A和蓝牙耳机F怎么选"
- ⚠️ **口碑解读**："蓝牙耳机A翻车点在哪"
- 🛡️ **售后问答**："蓝牙耳机A保修多久"
- 🚫 **超范围拒答**："iPhone 18 现在卖多少钱"

### 连续追问（展示多轮槽位继承）
```
第1轮：预算500以内推荐一副降噪耳机
        → 推荐蓝牙耳机A（¥349），理由含好评匹配/价格在预算内/次日达

第2轮：顺带问一下，除了耳机是不是还得买个充电线？有推荐吗
        → 不重新推荐耳机，识别为配套需求，推荐数据线E（¥39，编织60W快充）
        → 说明是给蓝牙耳机A配套的快充线

第3轮：那这个充电线有什么要注意的吗
        → 查数据线E的差评（接触不良/开裂），给避坑建议
```

## 效果评测

```bash
python -X utf8 benchmark.py --run --compare
python -X utf8 benchmark.py --baseline
```

同题库纯 API 直调任务完成率 40.7%（11/27）vs Agent 96.3%（26/27）；McNemar 配对检验 p=6.1e-05（b=15, c=0），统计显著。评测明细见 [docs/benchmark_report.md](docs/benchmark_report.md)，严谨对比实验见 [docs/rigorous_compare.md](docs/rigorous_compare.md)。
