## 对照实验：工具预加载 vs 全量注入

- 预加载（默认）：**10706** tokens/题
- 全量注入 6 工具 schema：**11149** tokens/题
- **整体节省 4.0%**（Dispatcher 按 task_type 只注入相关工具 schema）

### 分场景归因（整体 4% 被无工具场景稀释）

after_sales / refusal 两类（10 题）走 RAG 或拒答短路，两边都不注入工具 schema，天然拉平；
**工具真正进上下文的场景节省显著**（同题两轮对比抽样）：

| 题 | 预加载 | 全量 | 节省 |
| --- | --- | --- | --- |
| shop-rec-007（键盘推荐，3 轮工具循环） | 12270 | 17055 | **28.1%** |
| shop-cmp-001（双商品对比） | 18756 | 23132 | 18.9% |
| shop-aft-004（含多轮工具重试） | 11971 | 14385 | 16.8% |
| shop-rec-001 | 14745 | 17639 | 16.4% |
| shop-rev-005（评论检索） | 15897 | 18994 | 16.3% |

结论：工具调用轮次越多、schema 注入次数越多，预加载收益越大（每轮每个无关工具的 schema
都会重复计费）。简历口径建议写"工具密集场景节省 16-28%"而非笼统整体值。

## 已知波动（诚实记录）

- 任务完成率在 92%~96% 间随模型采样波动（单轮 ±1 题）：波动源集中在①引用编号偶发越界
  （如 shop-aft-004 本轮 [n] 超出资料范围）、②"质量"类同义改写（做工/连不上）；
  Reflector 修复可覆盖多数，不能覆盖全部——这正是评测存在的意义。
- 指标全部确定性规则判定，零裁判 token；复现命令见下。

## 对照实验：Agent vs 纯 API 调用

> 基线定义：同 25 题直接问 LLM（system=通用导购助手），不给工具、不给知识库、不拆任务、无记忆。同一套确定性指标评分（基线无意图分类，拒答判定靠措辞规则，工具命中率/引用可验证率对基线不适用，记 N/A）。

| 方案 | 任务完成率 | 拒答正确率 | 平均 tokens/题 |
| --- | --- | --- | --- |
| 纯 API 调用（基线） | 0.48 | 0.84 | 718 |
| **ShopPilot Agent** | **1.00** | **1.00** | 10706 |

> 公平性说明：Agent 完成 1.0 也偏**宽松**——部分对比题的商品名在题面里自带（must_contain 平凡通过），
> 且本轮 Agent 侧引用可验证率为 0.96（见明细）；即按最宽松口径，纯 API 仍差 52 个百分点。

**定性样例（shop-rec-001）**——纯 API 无法访问商品池/评论/知识库，直接**编造商品与价格**：

> 500元以内降噪耳机，建议先分两类选：**真无线入耳式**更适合通勤、地铁、运动；**头戴式**降噪和续航通常更强，但夏天闷、便携性差。

### 推荐清单（参考价，实际以电商实时价为准）

**1. 华为 FreeBuds 6i：约399—499元**
- 适合：通勤、地铁、公交，想要强降噪和稳定连接
- 优点：降噪能力在同价位比较突出，佩戴轻，通话和连接…
> 失败点：缺关键词：蓝牙耳机A（编造了商品池外的商品与价格）

**基线失败分布（25 题中 13 题失败）**：
- **编造商品/价格**（5 题推荐类全灭）：无商品池可查，凭训练语料编"华为 FreeBuds 6i 约 399-499 元"；
- **该拒答时硬答**（shop-ref-001/002/003/004 全灭）：给 iPhone 18 报价、写骂人回评文案、推荐爬山景点、给库外"蓝牙耳机Z"编参数——**拒答正确率 0.84 的 4 个失分全在这里**；
- **售后数字不准**（aft-001 保修期、aft-005 客服时间）：无知识库可引，靠常识猜；
- 对比/口碑类部分通过属**题面自带商品名的宽松口径**（见上公平性说明）。

结论：基线用 1/15 的 token（718 vs 10706）换来 48% 的完成率和 4 处该拒未拒——
**Agent 的价值不在模型，而在约束模型输出的系统**：商品池兜底（不编造）、知识库引用（数字可溯）、
拒答短路+双闸（该拒绝就拒绝）、Reflector 自检（错了我知道）。
